# 回归测试使用说明（ctfy-agent）

> 配套脚本：`tools/regression/run.py`。一次运行 = 产出**一条 JSON 记录**，字段定义见
> [`回归测试字段表.md`](./回归测试字段表.md)（字段的权威 schema）。改代码后重跑，用这些字段
> 与基线逐项比对，发现回归。
>
> 设计原则：**非侵入埋点**。脚本用 `Counting*` 包装器包住 agent 的各端口
> （`PlatformPort` / `LLMPort` / `ExecutionPort` / `ClockPort`）来采集数据，
> **不改** `agent/domain`、`agent/ports`（冻结契约）或 `agent/adapters`。

---

## 0. 快速上手

```bash
# 冒烟（无网络、无需 secret.env，确定性）——先跑这个确认链路通
python tools/regression/run.py --mode smoke

# 存一个基线（把本次记录另存为 regression/baseline.json）
python tools/regression/run.py --mode smoke --save-baseline

# 之后每次改代码重跑 smoke，自动与基线逐项比对并打印 PASS/WARN/FAIL
python tools/regression/run.py --mode smoke
```

> Windows 本机请用项目要求的 Python 3.11+ 直接运行（例如
> `python tools/regression/run.py ...`）。脚本会自动把仓库根加入 `sys.path`，
> 所以从仓库根目录运行即可。

## 1. 三个档位（--mode）

| 档位 | 连不连真实平台 | 需要 secret.env | 会不会花钱/发请求 | 用途 |
|---|---|---|---|---|
| `smoke` | 否（用 `agent/testing/fakes`） | 否 | 否 | CI/本地每次改代码的确定性回归基线 |
| `integration` | 是（**只读**） | 是 | 少量（4 次只读 API + 1 次网关调用） | 验证真连 CTFY + 智谱 GLM 的链路、鉴权、解析 |
| `solve` | 是（完整做题） | 是 | 是（跑 `Coordinator.run()`） | 开赛后的端到端成绩回归 |

### smoke
- 用 `FakePlatform / FakeLLM / FakeExecution / FakeClock` 构造一套假适配器，跑**完整**
  `Coordinator.run()`。假模型每轮回一个 `execute` 工具调用，命令回显里带一个假 flag，
  solver 抽取并提交，`FakePlatform` 判 `CORRECT` → 解出。
- 内置 3 道假赛题（web/easy、crypto/medium、pwn/hard），用来填充 `by_category` /
  `by_difficulty` / `per_challenge`。
- **确定性**：无真实 IO、无真实时钟，反复跑成绩类字段完全一致
  （如 `questions_solved=3`、`solve_rate=1.0`、`tokens_per_solve=52.0`）。实例启动、提交和问题刷新会分别计入 `api_calls_by_method`，不应把旧版请求总数当作固定契约。
- **无需网络、无需 secret.env**，适合做默认基线与 CI 门禁。

### integration（只读探测）
- 读取 `docs/secret.env`（`KEY=value`；优先用 `python-dotenv`，没有则脚本按行解析，
  支持 `#` 注释、可选 `export ` 前缀、去引号）→ 写入 `os.environ` → `Settings.from_env()`。
- 用**真实适配器**（`CtfyRestAdapter` + `GatewayAdapter`，注入计数用的 httpx 传输层）做
  **只读**探测：`whoami` → `list_challenges` → 对第一题 `get_challenge` → `scoreboard`；
  再**真调一次** `gateway.complete()`（提示 `reply with exactly: pong`，`effort=low`）。
- **不启动实例、不提交**。用于确认：token 有效、平台返回能被适配器正确解析、GLM 网关
  （anthropic 兼容，`glm-4.6`）能通且 token 计数正确。
- `competition` 从 env（`CTFY_EVAL_COMPETITION_ID`）取，可用 `--competition <id>` 覆盖。

### solve（完整做题，开赛后用）
- 用真实适配器跑**完整** `Coordinator.run()`（含 `SubprocessAdapter` 执行器）。
- **开赛前**平台会对 `instances` / `submissions` 返回 `competition_paused`（HTTP 403）。
  实例启动由适配器按 `retry_after_s` / `Retry-After` 经时钟端口等待后重试，不再返回伪造的 STOPPED 实例；
  提交暂停仍映射为 `VerdictStatus.PAUSED`，计入 `_notes` 与 `verdicts.paused`。启动阶段的暂停体现在 HTTP 与等待统计中。
- 有整体墙钟上限 `--timeout`（默认 1800s）兜底；超时记 `stop_reason=timeout` 仍写记录。
  真实做题耗时还受 `CTFY_EVAL_MAX_TURNS` / 预算约束。

## 2. secret.env（integration / solve 需要）

脚本默认读 `docs/secret.env`（可用 `--secret-env <path>` 换）。需要的键与
`agent/config.py` 的 `Settings.from_env()` 一致：

```ini
CTFY_PLATFORM_URL=https://<平台域名>
CTFY_TOKEN=pf_xxx_你的scoped_token
CTFY_EVAL_COMPETITION_ID=c0d8b4e3dd3b42c095d63d7dfa66431f
LLM_FLAVOR=anthropic
LLM_BASE_URL=https://open.bigmodel.cn/api/anthropic
LLM_API_KEY=<智谱 key>
LLM_MODEL=glm-4.6
# 可选：CTFY_EVAL_MAX_TURNS=、CTFY_EVAL_MAX_TOKENS=、CTFY_WORK_DIR=
```

> 安全：`result.json`、回归 JSON、Markdown、trace、终端与本次新生成的基线统一脱敏。
> 清洗在预览截断、JSON 编码之前进行，覆盖控制凭证及其 OpenAI / Anthropic 环境别名；
> 保存的诊断还会隐藏 Bearer 值。`meta.llm_base_host` 仅保留 host，不保留 URL 凭证。
> `artifact.no_secret_leak` 检查本次明确列出的全部产物及待输出的 stdout / stderr，
> JSON 按解码后的结构检查；缺失、解析失败、扫描异常或检测到泄露均失败，
> 记录中保留 `false`，运行器以非零退出且不打印未通过审计的内容。
> 正式记录先标记为未通过，完整候选产物审计通过后才原子提交，记录最后发布；
> 写入或审计中断不会提前留下 `no_secret_leak=true`。

## 3. 产物位置与 .gitignore

- 记录：`regression/runs/<run_id>.json`（`run_id` = `时间戳Z-git短hash`，如
  `20261022T065121Z-8972aab`）。
- 该次运行写出的 `result.json` 副本：`regression/runs/result-<run_id>.json`（供 `artifact.*`
  校验，一并保留便于复盘）。
- 基线：`regression/baseline.json`（用 `--save-baseline` 写入；可用 `--baseline <path>` 换）。
- 可用 `--out <dir>` 改记录输出目录。

**请把运行产物加入 `.gitignore`**（本仓库的 `.gitignore` 已忽略 `scratch/`，但尚未忽略
`regression/runs/`）。推荐在仓库根 `.gitignore` 增加一行：

```gitignore
regression/runs/
```

> 仅本次新生成且通过安全审计的基线可作为共享候选；是否提交入库由团队决定。
> 旧日志、旧基线不会被自动清理，分享前需另行检查。若不想保留产物在工作区，
> 可用 `--out scratch/reg` 写入已被忽略的 `scratch/`。

## 4. 基线比对与阈值

无 `--save-baseline` 且基线存在时，脚本自动比对并打印逐项 `PASS/WARN/FAIL` 与总判定。
判定分三类（见字段表「回归判定」）：

- **红线（硬失败，任一不满足即总判定 FAIL，与基线无关）**：
  `exit_code==0`、`result_json_written`、`result_json_valid`、`no_secret_leak`、`exceptions==0`。
- **成绩回归（下降超阈值 → WARN/FAIL）**：`questions_solved`、`solve_rate`、
  `time_to_first_flag_s`（变慢）、`wrong_rate`（变高）、`tokens_per_solve`（变高）。
- **性能回归（超阈值 → WARN）**：`total_wall_s`、`model_call_s_p95`、`api_calls_total`。

阈值配置文件：[`tools/regression/thresholds.json`](../../tools/regression/thresholds.json)。格式：

```jsonc
{
  "redlines": ["exit_code_zero", "result_json_written", "result_json_valid",
               "no_secret_leak", "exceptions_zero"],
  "metrics": {
    // 字段用点路径定位到记录里（如 solving.solve_rate）
    "solving.solve_rate": {
      "direction": "higher_better",  // 越高越好
      "min_ratio": 0.95,             // 本次/基线 < 0.95 触发
      "severity": "FAIL"             // 触发级别
    },
    "timing.total_wall_s": {
      "direction": "lower_better",   // 越低越好
      "max_ratio": 1.2,              // 本次/基线 > 1.2 触发
      "severity": "WARN"
    },
    "verdicts.wrong_rate": {
      "direction": "lower_better",
      "max_abs_increase": 0.1,       // 绝对增量 > 0.1 触发
      "severity": "WARN"
    }
  }
}
```

- 本次或基线缺该字段、或非数值 → 该项记 `SKIP`（不影响总判定）。
- 想新增一项回归守护：往 `metrics` 里加一个「点路径 → 规则」即可，无需改脚本。
- **基线应按档位分别保存**：不同 `--mode` 的字段规模完全不同，不要拿 smoke 基线比
  solve 记录。脚本会在档位不一致时打印提醒；建议用
  `--baseline regression/baseline.smoke.json` 这类分档位基线。

## 5. 字段来源与「暂不可得」说明

字段含义以 [`回归测试字段表.md`](./回归测试字段表.md) 为准。采集方式：

- **外部测量（📏）**：`run_id`、`git_commit/dirty`、`python/platform`、墙钟、`result.json` 校验等——脚本直接取。
- **包装器埋点（🔧，非侵入）**：`api_calls_total`、各 `VerdictStatus` 计数、`instances_started`、
  各端口每次调用耗时、`time_to_first_flag_s`、`model_calls`/token、`http_4xx/5xx`、
  `transport_errors`、`wire_requests`、`retry_after_waits` 等——由 `Counting*` 包装器采集。
- **RunResult/Budget（✅）**：`questions_solved`、`fully_solved`、`turns_used`、token、
  `tool_calls_made`、`stop_reason`。

以下字段**在不改冻结契约的前提下无法从端口边界观测**，记为 `null` 并在此说明（待日后在
控制循环内加轻量计数器时补齐；补齐不应改 `state.py`/`ports`）：

- `solving.gated_unlocked`、`verdicts.hallucinated_submits`、`model.invalid_tool_calls`、
  `model.lanes_launched`/`escalations`/`racing_used`、`stability.stalls_detected`：均为 solver/
  coordinator 的**内部状态**，端口外看不到。
- `budget.cost_usd`/`budget_exhausted`：需单价表与控制循环注入。
- `per_challenge[].wall_s`/`turns`/`tokens_total`：`RunResult` 只汇总到 run 级，无法非侵入拆分到每题
  （但每题的 `submissions`/`wrong`/`capped` 可由 `CountingPlatform` 按 `challenge_id` 拆出）。
- `meta.competition_title`：冻结的 `/me` 端口只回 `Account(id, name)`，暂无赛事名字段。

**近似字段（已在字段上标注思路）**：`platform.api_retries` 用「返回 429/5xx 或传输异常的响应数」近似；
`retry_after_waits` 用「带 `Retry-After` 头的响应数」统计；`clock_sleeps`/`clock_wait_s_total`
统计经 `ClockPort.sleep` 的礼貌退避/等待（含 paused 轮询）。

## 6. 开赛前 / 开赛后差异

| | 开赛前（现在） | 开赛后 |
|---|---|---|
| `integration` | 可正常只读探测；`scoreboard` 多为空或 0 分 | 同样可用，数据变丰富 |
| `solve` | 实例启动遇暂停时等待会话恢复；整体超时记录 `stop_reason=timeout`。仅提交阶段的 PAUSED 判定计入 `verdicts.paused`，未解题不会报告全部完成 | 正常做题，`questions_solved`/`solve_rate` 等成绩字段生效，开始有真实回归意义 |
| 基线 | 先用 `smoke` 基线守住「链路不崩、无泄露」红线 | 开赛后用 `solve` 跑若干次，挑一条稳定的存为 solve 基线 |

## 7. 自测与 CI

```bash
# 产出一条 smoke 记录（应 exit 0、解出 3/3）
python tools/regression/run.py --mode smoke

# 项目质量门禁保持全绿
python -m pytest -q
python tools/check.py     # ruff + import-linter + pytest（+ mypy 建议）
```

脚本自身**绝不以非零码崩溃退出**：任何内部异常都会兜底写出一条记录
（`stop_reason=runner_error:*`，`exit_code=1` 记入 `stability`），便于定位。

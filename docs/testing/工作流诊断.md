# ctfy-agent 工作流诊断与优化清单

> 2026-10-22。面向团队。结论经**源码逐行核对**（非 agent 报告转述）+ **同模型对照实验** + **文献**三方印证。
> 核心判断：**解题瓶颈在 scaffold（控制流 / prompt / shell 反馈），不在模型，也不在工具链。**

## 1. 对照实验（方法）

同一道题 SAMPLE-005（misc，多层套娃 zip，easy，纯附件无实例），**同一个底层模型 glm-5.3**，只换 agent 框架：

| 框架 | 模型 | 结果 | 步数 | 墙钟 |
|---|---|---|---|---|
| Claude Code | glm-5.3 | ✅ 解出 | **5 步** | 119s |
| **ctfy-agent（本项目）** | glm-5.3 | ❌ **18 turns 未解**（`incomplete`） | — | 34s 空转 |

flag 一致（`FLAG{archives-stack-just-keep-unzipping-7b2c19}`）且独立核验（hexdump 逐字节 + sha256）。
→ 工具链（两边都只用 unzip/cat/grep）、满配镜像、模型都不是瓶颈；**差距全在 agent 框架本身**。

复现命令见 §6。

## 2. 根因（源码核对，带行号）

**冒烟枪**：停因是 `incomplete` 而非 `budget_exhausted` —— 预算没见底，agent 是**被 stall 停损逼着主动退出**。退出由三件事叠加：

1. **3 条克隆 lane 瓜分同一预算**。`coordinator.py:34` easy=3；`:60-69` `_models()` 返回 `[primary, primary, primary]`（同模型、同 prompt、零多样性）；`:85` 一个 `Budget` 被全部 lane 共享。单条链真实深度只有 ~1/3。
2. **stall 停损把正常解包判成空转**。`policy.py:30` `stall_limit=6`；`solver.py:358-362` 进展只认 flag 外形，`unzip` 解出新层、`cat` 读到新内容都记 `stalled+1`。3 lane × 6 步 ≈ 18 turns，与实测吻合。
3. **循环近乎失忆**。`solver.py:269-273` plan 初始化为 3 条通用占位后，**整个循环再没被赋值**；`recent_obs` 是单槽、每轮覆盖。模型每轮只看到同一份静态 plan + 最近一次观察，于是反复从头 `ls`/`find`。
4. **硬 bug：prompt 与 shell 实现契约矛盾**。`prompts.py` 告诉模型"每次 execute 是全新 shell、`cd` 不保留"，但 `subprocess_exec.py` 的 `_ShellSession` 是**持久有状态 shell**（`cd`/env 跨命令保留）。模型按"永远在工作区根"用相对路径 `archive.zip`，而 cwd 已漂到子目录 → `unzip: cannot find archive.zip`。

## 3. 文献印证

- **EnIGMA（CTF agent SOTA, ICML'25）** 命名的失败模式 **"soliloquizing"**：模型臆造观察、不真正与环境交互 —— 对应症状「反复列目录却不 `cat` 文件内容」。
- **doom-loop 检测**：追踪重复的 `(tool, 参数)` 对 + **硬停止**（模型会无视文字警告，绕不过真 stop）—— 对应「多 lane 重复 recon」。
- **SWE-agent 的 ACI（Agent-Computer Interface）**：工具反馈格式是成败主杠杆，模型对分散性上下文极敏感 —— 对应「观察截断 / 缺 cwd / 噪声」。
- **ENIGMA+**：按步数（非金额）cap、把 context-heavy summarization 换轻量 —— 对应「调度 / 预算 / 记忆」。

## 4. 优化清单（ROI 从高到低，已核对 + 架构兼容标注）

每条标注是否触及 **frozen 契约 / state.py schema（BOUNDARY）**。结论：**几乎全部在 domain / adapter 内部，不碰契约。**

| # | 改动 | 根因（文件:行） | 碰契约？ |
|---|---|---|---|
| 1 | **easy/medium 收敛成单条深链**（或改成真·多样竞速，别克隆） | `coordinator.py:34,60-69,85` | 否（domain 常量）。但触及 ADR-0002 §6 设计，见 §5 |
| 2 | **修 stall 停损**：新文件 / 新 stdout 内容 / 新解出归档都算 progress；`stall_limit` 抬到 10-12 | `policy.py:30`，`solver.py:358-362` | 否（domain 逻辑） |
| 3 | **shell 契约一致**：保留持久 shell 则改 prompt 说实话 + 每轮注入 cwd（推荐）；或回无状态 | `prompts.py`（无状态声明）↔ `subprocess_exec.py` `_ShellSession`（持久） | 否（adapter / prompt 内部），见 §5 |
| 4 | **每轮观察补 cwd + 工作区绝对路径** | `solver.py:398-414`（观察头无 cwd）、`:221-254`（goal 无绝对路径） | 否。用「命令后 `; pwd`」或读 `workdir` 规避，不必给 ExecResult 加字段 |
| 5 | **候选 flag 在完整 stdout 上扫描**，而非截断后的观察 | `solver.py:47`（`_OBS_TAIL=1200`）、`:407`（先 `_tail`）、`:340`（在截断文本上 `_find_candidates`） | 否（solver 内部，`ExecResult.stdout` 原文可取） |
| 6 | **给循环装记忆**：回传模型写的 plan + 保留近 K 步 `(命令, 短观察)` | `solver.py:269-273`（静态 plan）、`:274`（单槽 obs） | 否（都是 `solve()` 局部变量，**非 state schema**） |
| 7 | **把 read_file 作为一等工具暴露给模型** | `solver.py:184-218` `_tools()` 只给了 execute+submit_flag | **否——`ExecutionPort.read_file` 早已存在**（`execution.py:30`），只在 solver 加个 ToolDef |
| 8 | **核对提交门禁**：非 QA 强制 `word{...}` 外形可能吞掉裸值答案 | `policy.py:14` `_FLAG_RE`、`solver.py:448` | 否（domain）。需先核实题面 fmt |
| 9 | **默认开推理档位** effort=high（规划轮） | `solver.py:291-293` 不传 effort | **否——`LLMPort.complete` 早有 `effort` 参数**（`llm.py:20`，默认 medium），solver 没传而已 |

小问题（顺手）：`subprocess_exec.py:313` stderr 并入 stdout 后，`solver.py:410-413` 的 `stderr:` 分支对持久 shell 已成死代码；`subprocess_exec.py:142-148` `new_workspace` 只拷顶层文件，子目录附件不 seed。

## 5. 架构兼容性结论

- **不需要改 frozen ports、不需要开 ADR**：`read_file`（#7）和 `effort`（#9）两个端口能力**早已存在**，只是上层没用；其余改动在 domain / adapter 内部逻辑。
- `plan` / `recent_obs` 是 `solver.solve()` 的**局部变量**，改"循环记忆"**不碰 `state.py` schema**（BOUNDARY 安全）。
- 两个**设计张力**（需团队拍板，非硬冲突）：
  1. **#1 lane 策略 vs ADR-0002 §6「多 lane 竞速」**。当前 `_models()` 返回克隆，**没兑现 ADR 的"over models"本意**（本意是不同模型/策略竞速）。砍单链或改真·多样竞速，都是**修正实现对 ADR 的偏离**，但动了 swarm 核心，需知会。
  2. **#3 持久 shell（`6a93b02` 刚引入）的取舍**。建议**保留持久 shell + 修 prompt 诚实 + 每轮注入 cwd**，留住收益、补上契约，而非回退无状态。

## 6. 推荐落地顺序

**先做（本次失败的半数解药，改动极小）**：
1. #1 easy/medium 收敛单深链（一行字典）。
2. #2 修 stall（解包/读内容算 progress + `stall_limit` 10-12）。
3. #3 shell 契约一致（保留持久 shell + prompt 说实话）+ #4 观察补 cwd。

**紧随（乱逛最深的根因）**：#6 循环记忆（便宜版：把模型自己写的 plan 捕获、下一轮回传）。
**顺手低成本**：#5 完整 stdout 扫 flag、#7 read_file 工具、#9 effort=high。
**改完**：用同一道 SAMPLE-005（必要时加一道逆向题）重跑，看「同模型解题率」是否拉起来。

## 8. 优化落地与实测（2026-10-22）

top-3+ 已落地并推 main（commit `1e768b4`），门禁全绿（131 passed，未碰 frozen ports / state schema）。

**核心控制变量验证**（同镜像 `ctfy-agent:full`、同模型 glm-5.3、同题 SAMPLE-005，唯一变量 = agent scaffold 新旧）：

| 指标 | 改前（镜像内旧码） | 改后（挂新码） |
|---|---|---|
| 结果 | ❌ incomplete | ✅ completed |
| 解出 | 0 | **1（correct）** |
| turns | 18（被 stall 逼退） | **4** |
| tokens | 6208 | 2617 |

trace 印证每项优化生效：turn1 `pwd && ls`（**cwd 可见**）→ 递进解包 → turn4 `cat` 所有内层文件读到 `ticket-id: FLAG{...}` → 提交 CORRECT。**改前反复列目录 18 轮，改后 4 轮读到底**。

**扩展题受限 + 发现实例泄漏（高优先待办）**：其余样题多需 `start_instance`。排查 429 的根因**不是速率限流**，而是 **平台每队实例配额 ≈ 1 + harness 从不释放实例**——`PlatformPort` 只有 `start_instance`、无任何 release/stop 方法，`coordinator`/`solver` 在 solve 结束也不销毁实例。于是第一道实例题起的实例一直占着配额（ttl 3h，实测 `GET /instances` 只有 1 个 SAMPLE-002 实例 status=ready），后续题全部 429。

> ⚠️ **赛时关键**：不修则解完第 2 道实例题就卡死在 429。平台**支持** `DELETE /instances/{id}`（实测返回 `{"status":"stopped"}`），修法明确：`PlatformPort` 加 `release_instance`，`solver`/`coordinator` 在 `finally` 释放。**此改动碰 frozen `PlatformPort` → 需 ADR + 团队协调**，故未在本轮自主改动，列为最高优先待办。本轮已手动释放实例（`DELETE`）解锁测试。

web/checker 题（001/006-009/013）对"需真实利用 + checker 验证"的 GLM 几乎无望。实例题待逐题手动管理配额、或修复 release 后系统评估解题率。

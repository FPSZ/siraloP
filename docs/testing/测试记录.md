## 第一次测试（2026-10-23）：20 道公网可达练习题，难度递增

### 环境

- 代码：commit `10118fe`（含"已拒答案记忆 + 空输出标记"；dsh 的头+尾截断/连续重复提醒经实证有害已弃）。
- 模型：**deepseek-flash**（=DeepSeek-V4.1-Flash-1017）。
- 运行：满配镜像 `ctfy-agent:full`，`solve` 档，`--timeout 600 --max-turns 40`，**每题跑 1 次（n=1）**。
- 用例选取：从平台 **247 道公网可达（`network_topology=simple`，`*.node4.ctfy.run`）** 练习题中，按难度递增、每题 `solves>0`（已有队伍解出＝可解可达）挑 20 道；跨 CTFARENA / SQLILABS / UPLOADLABS 三套件。全部 `dynamic` 可判分。
- 每题起实例传该题**所属竞赛的 competition_id**，提交带 `instance_id`，跑完释放实例。

### 按套件

| 套件 | 解题率 | 说明 |

| SQLILABS | 4/4 | SQL 注入，全解 |

### 结论

1. **失败模式统一 = "打不通就狂刷错 flag"**：5 道失败全是 CTFARENA，分别错提交 5/20/27/28/29 次。现有"已拒答案记忆"只拦**重复同一个**答案，拦不住模型生成**多个不同**错答。**这在真实赛场会直接撞爆错误提交 cap——是当前最大失分点。**
2. **能力缺口在 CTFARENA 式访问控制/现代 web 利用**；SQLi、文件上传很稳（连 hard 都干净解）。
3. **方差**：n=1，中/难档存在方差（上一轮 SAMPLE-009/011 曾 solve↔fail 翻转），严谨评测应每题 n≥3 取解率。

### 同模型对照组：dsh（DeepSeek Harness，同 deepseek-flash）

为区分瓶颈是 scaffold 还是模型，挑 5 道（含 ctfy 做出的和没做出的）交给 dsh 跑同一个
deepseek-flash（起公网实例→dsh 找 flag→提交平台判分）。原始日志
`scratchpad/runs20/DSH_CONTROL.log`。

| 题 | ctfy-agent | dsh（同模型） | dsh 用时 / 手法 |
|---|---|---|---|
| SQLILABS-001 | ✓ | ✓ | 21s，UNION 注入 |
| CTFARENA-003 | ✓ | 首轮推对*（解析脏字符未判对）/重验超时 | 23s，IDOR |
| CTFARENA-006 | ✗ 错29 | **✓** | 61s，`file://` LFI 读 `/flag` |
| CTFARENA-002 | ✗ 错20 | **✓** | 33s |
| CTFARENA-004 | ✗ 错28 | **✓** | 279s |

\* CTFARENA-003 首轮 dsh 推出了正确 flag，但输出带 `</result>` 标签、被编排器提交逻辑带错；
重验遇方差超时。不影响头条结论。

**结论：瓶颈在 scaffold，不在模型。** ctfy-agent 失败并狂刷错 flag 的 3 道 CTFARENA，dsh 用
**同一个模型**全部干净解出。模型完全有能力打这些访问控制/LFI 题，是我们的 harness 拖住了它。
dsh 源码对照 + 2026 最新做法的差异与改造清单见 [scaffold调研与优化.md](scaffold调研与优化.md)。

### 下一步（ROI 从高到低；详见 scaffold调研与优化.md）

1. **重做观察截断**（别再每条尾截 500/1200；小输出留全、超大才头+尾、长输出落盘给指针 + findings 行）——首要短板，不改别的事倍功半。
2. **提交证据门 + 硬上限**：flag 必须在真实观察里出现过 + 去重 + 每题硬上限到顶认输——直击狂刷错 flag。
3. **plan 升级为诊断**（current_hypothesis / ruled_out / confirmation_step）。
4. 防循环杀重复但别杀探索；工具反馈补"失败先查"+落盘指针；侦察进 plan 模板而非堆提示词。

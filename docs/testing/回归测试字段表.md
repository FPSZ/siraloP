# 回归测试字段表（ctfy-agent）

> 每跑一次回归 = 产出**一条 JSON 记录**，字段如下。改动代码后重跑，用这些字段与基线逐项对比，发现回归。
> 目标：字段完整、精细、可取（标注来源），覆盖「时间 / 解题 / 判定 / 预算 / 模型 / 平台 / 稳定性 / 产物」八个维度。
>
> 记录文件：`regression/runs/<run_id>.json`；基线：`regression/baseline.json`。
> 采集方式：脚本（`tools/regression/run.py`）在跑 agent 的同时收集；部分字段来自 `RunResult`/`Budget`（已采集），部分需在控制循环里**埋点**（下方标注 🔧）。

术语：一次「运行(run)」= 对某个赛事(competition)跑一遍 agent；一个赛事含多个「赛题(challenge)」；一个赛题含多个「问题(question)」；提交一次答案得到一个「判定(verdict)」。

## 0. 记录顶层结构

```jsonc
{
  "meta":      { ...运行标识与环境... },
  "timing":    { ...时间与延迟... },
  "solving":   { ...解题与正确性... },
  "verdicts":  { ...判定统计... },
  "budget":    { ...预算与成本... },
  "model":     { ...模型与编排... },
  "platform":  { ...平台交互... },
  "stability": { ...稳定性与错误... },
  "artifact":  { ...result.json 产物校验... },

}
```

状态图例：✅ 已采集（RunResult/Budget 现有）｜🔧 需埋点（控制循环加计数/计时）｜📏 脚本外部测量（墙钟/结果文件）

## 采集状态与「需埋点」清单

**现已采集（无需改代码）**：`questions_solved`、`fully_solved`、`turns_used`、`tokens_input/output`、`tool_calls_made`、`stop_reason`、以及全部 📏 外部测量项（exit_code、result.json 校验、墙钟、git/env）。

**需埋点 🔧（建议做法：控制循环里加一个轻量 `RunStats` 累加器，由 ClockPort 计时、按 Verdict/类别计数，跑完序列化进记录）**：
1. 计时类：`time_to_first_flag_s`、各阶段/每轮/模型调用耗时 → 在 solver 循环用 `clock.now()` 打点。
2. 判定计数：correct/wrong/capped/ungraded/paused、`hallucinated_submits` → 在 `_submit` 分支里累加。
3. 分类/难度/每题：`by_category`、`by_difficulty`、`per_challenge[]` → coordinator 聚合每个 Swarm 结果时填。
4. 平台/模型计数：`api_calls_total`、`api_retries`、`retry_after_waits`、`instances_started`、`model_calls`、`lanes_launched`、`escalations`、`invalid_tool_calls` → 适配器/编排处累加。
5. 异常/停滞：`exceptions`、`stalls_detected`、`tool_timeouts`。

> 埋点原则：只加「纯计数/计时」的累加器，**不改** state.py / ports 冻结契约；累加器可作为可选参数注入 solver/coordinator，不注入则为 no-op（不影响现有 48 个测试）。

## 回归判定（怎么比对）

每次 run 产出记录后，与 `baseline.json` 比对，分三类：
- **红线（硬失败，任一不满足即 FAIL）**：`exit_code==0`、`result_json_written`、`result_json_valid`、`no_secret_leak`、`exceptions==0`。
- **成绩回归（下降超阈值即 WARN/FAIL）**：`questions_solved`、`solve_rate`、`time_to_first_flag_s`（变慢）、`wrong_rate`（变高）、`tokens_per_solve`（变高）。
- **性能回归（超阈值 WARN）**：`total_wall_s`、`model_call_s_p95`、`api_calls_total`。

阈值写在 `regression/thresholds.json`（如 `solve_rate` 不得低于基线 95%、`total_wall_s` 不得高于基线 120%）。脚本输出 `PASS/WARN/FAIL` 并给出逐项 diff。

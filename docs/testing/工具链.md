# CTF 工具链（竞赛镜像）

本文件记录竞赛镜像 [`Dockerfile`](../../Dockerfile) 里给 agent 装的 CTF 工具、为什么这么选、
以及刻意排除/暂缓的部分。经一次按方向并行的联网调研汇总而来；选择的第一标准是
**「最适合 AI agent 经非交互、可恢复工作区状态的 Bash 命令使用」**，而不是「最高级/最流行」。

## 选择原则：什么叫「AI 友好」

agent 通过**无 TTY 的受监督 Bash 命令**（见 [`SubprocessAdapter`](../../agent/adapters/execution/subprocess_exec.py)）
驱动工具；cwd、变量与函数由工作区快照恢复，不复用活 shell。也会写 Python。因此优先：

- **可脚本化 / 非交互**：有 CLI flag 或 Python API，一条命令出结果。排除只能 GUI/TUI 交互的
  （IDA 图形界面、Wireshark GUI、stegsolve、Burp 等）。
- **输出确定、可管道解析**：纯文本、最好有 JSON。
- **离线可用**：竞赛运行时 `internet_policy=deny`，工具及其数据必须构建期全部装好。
- **轻量优先**：同等能力选体积小、无重依赖的。

镜像里为此统一做了 **shell 工效** 设置（`Dockerfile` 的 `ENV`）：关掉所有分页器
（`PAGER=cat` 等，避免无 TTY 的命令等待分页器交互）、关颜色
（`NO_COLOR=1`，避免转义码污染解析）、`PYTHONUNBUFFERED=1`、`PWNLIB_NOTERM=1`（pwntools 不吐终端控制码）、
gdb `set pagination off / confirm off`。

## 构建约束（GFW 后）

- 基座 `python:3.13-slim` 用**本地已有镜像**（不走 Docker Hub）。
- apt 走**清华 Debian 镜像**、pip 走**清华 PyPI**、gem 走**清华 rubygems**。
- 分层：base → rev/pwn → forensics → crypto/web → pip → gems → radare2(源码) → agent。
  某一层失败不影响已缓存的前层，便于单层修复重试。

## 各方向工具（默认镜像内）

| 方向 | 核心（必装） | 补充（建议） |
|---|---|---|
| **pwn** | `pwntools`(纯 Python，交互/ELF/ROP/shellcraft 一把梭)、`gdb`+`gdb-multiarch`(`--batch -ex` 脚本化)、`ROPgadget`、`patchelf`、`checksec`、`binutils`/`file` | `ropper`、`one_gadget`、`seccomp-tools`(gem)、`strace`/`ltrace`、`qemu-user-static`(跨架构) |
| **rev** | `radare2`(+`r2pipe` 脚本化，源码装)、`binutils`、`strace`/`ltrace`、`upx-ucl`、`binwalk` | `capstone`/`unicorn`/`keystone`、`uncompyle6`、`pyinstxtractor-ng` |
| **crypto** | `pwntools`、`pycryptodome`、`gmpy2`、`sympy`、`python-flint`、`z3-solver`、`openssl` | `fpylll`(格)、`cryptography`、`john`、`gmp-ecm`、`name-that-hash`、`xortool`、`libnum` |
| **web** | `curl`、`jq`、`requests`、`nmap` | `httpx[cli]`、`sqlmap`(`--batch` 非交互)、`ffuf`/`gobuster`/`dirb`、`pyjwt`、`beautifulsoup4`/`lxml` |
| **forensics/misc** | `file`、`binwalk`、`exiftool`、`foremost`、`steghide`、`stegseek`、`zsteg`(gem)、`zbarimg`、`pngcheck`、`poppler-utils`、`sleuthkit` | `scalpel`、`outguess`、`qpdf`、`testdisk`、`sqlite3`、`fcrackzip`/`pdfcrack`、`scapy`、`pillow`/`numpy` |

每个工具的非交互用法示例见调研原始结果（journal）。几个代表：

- `pwn checksec ./chall`；`python3 -c "from pwn import *; e=ELF('./chall'); print(e.checksec())"`
- `gdb -q --batch -nx -ex 'file ./chall' -ex 'break main' -ex run -ex 'info registers' -ex quit`
- `r2 -q -c 'aaa; afl; pdf @ main' ./chall`（或 `python3 -c "import r2pipe; r=r2pipe.open('./chall'); r.cmd('aaa'); print(r.cmd('pdf @ main'))"`)
- `ROPgadget --binary ./chall --ropchain`
- `checksec --output=json --file=./chall`（结构化，最好解析）

## 刻意排除（流行但不适合本场景）

- **GUI/TUI 工具**：IDA GUI、Ghidra GUI、Wireshark GUI、stegsolve、Burp —— AI 用不了图形界面；
  需要时用其 headless/CLI 形态（Ghidra `analyzeHeadless`、`tshark`）。
- **需联网的在线服务**：factordb 在线查询、`libc-database ./get`、`pwninit` 默认自动下载 ld/libc ——
  运行时离线用不了；要用得构建期预置数据（见下「可选重型」）。
- **SageMath**：Debian 13 已移除 apt 包，离线只能 conda 预下 2–4GB 或源码编译数小时，收益/体积不划算；
  常见需求用 `sympy`/`python-flint`/`fpylll`/`gmpy2` 覆盖。
- **hashcat**：纯 CPU 容器还要装 OpenCL 运行时，重且 CTF 里本地爆破多用 `john` 即可。

## 可选重型层（默认不装，按需开）

这些价值高但重/构建期需额外网络，默认**不在**镜像里，按需单独加层：

- **angr**（符号执行，纯 Python，数百 MB）：`pip install angr angrop`。复杂路径/自动求解时加。
- **Ghidra headless**（反编译，~GB，需 JDK）：下 GitHub release zip + `apt openjdk-21-jre-headless`，
  用 `analyzeHeadless` + `pyghidra` 脚本化。radare2 的反编译不够时再上。
- **volatility3**（内存取证）：`pip install volatility3` + **构建期预置符号包**（win/linux/mac）。
- **pwndbg/GEF**（gdb 增强）：需构建期从 GitHub 拉；默认用裸 `gdb --batch` + pwntools 自带 gdb 集成兜底。
- **libc-database / pwninit**：构建期预建索引 + 预下候选 libc（`needs_prebaked_data`）。
